# KiCad schematic and PCB Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A generated KiCad 10 project under `hardware/kicad/` with an ERC-clean schematic, a DRC-clean fully routed 70 × 50 mm two-layer PCB, and committed fab outputs (Gerbers, drill, BOM, PDF, renders).

**Architecture:** Pure-Python modules under `hardware/kicad/` derive the netlist from `docs/board/data.py` (through `gen.check()` there), write the schematic as KiCad s-expressions, build the board through the `pcbnew` Python module, and call `kicad-cli` for ERC, DRC with schematic parity, netlist read-back and every export. All geometry (schematic placement and wires, PCB placement, routes, silkscreen) is data in `layout.py`. Two hand-written library files hold the Mini-360 symbol and the Mini-360 and polyfuse footprints.

**Tech Stack:** Python 3 (stdlib only: `unittest`, `uuid`, `json`, `zipfile`, `subprocess`), KiCad 10.0.6 (`kicad-cli`, `pcbnew` module, stock libraries at `/usr/share/kicad/{symbols,footprints}`).

**Spec:** `docs/superpowers/specs/2026-11-22-kicad-pcb-design.md`

## Global Constraints

- KiCad 10.0.6 only; no pip packages. Tests run with `python3 -m unittest discover -s hardware/kicad/tests -v` from the repo root.

- Title block: title `ESP8266 fan controller`, rev `1.0`, date `2026-11-22`, comment 1 `https://github.com/vvsosed/esp8266-fan-controller`.

  SYMBOL_DIR = Path("/usr/share/kicad/symbols"); PROJECT_SYM = Path(__file__).parent / "fan_controller.kicad_sym"
  def load_symbol(lib_id: str) -> list        # flattened `(symbol "Lib:Name" ...)`: `extends` resolved (parent graphics + child properties), sub-units renamed `Name_u_s`, no `extends`
  def pin_offsets(symbol: list) -> dict[str, tuple[float, float, int]]   # pin number -> (x, y, angle) in library coordinates (y up), all units
  @dataclass
  class Place: ref: str; at: tuple[float, float]; rot: int = 0; mirror: str | None = None   # mirror "x" or "y", KiCad's meaning
  def pin_xy(place: Place, offset: tuple[float, float, int]) -> tuple[float, float]   # where KiCad draws that pin's end on the sheet (y down)
  class Schematic:
      def __init__(self, title: dict): ...                         # title/rev/date/comment1; paper A4 landscape
      def add_part(self, part: Part, place: Place, value_at=None, ref_at=None) -> None   # symbol instance with Reference/Value/Footprint/Datasheet/Description properties, (instances (project "fan_controller" (path "/<ROOT>" (reference ref) (unit 1))))
      def add_power(self, net: str, at, rot=0) -> None             # power:+12V / power:+3V3 / power:GND instance with Value = net (reference "#PWRnn", hidden)
      def add_flag(self, at) -> None                               # power:PWR_FLAG
      def add_label(self, net: str, at, rot=0) -> None             # local (label ...), justify by rot
      def add_wire(self, pts: list[tuple[float, float]]) -> None   # one (wire) per segment
      def add_no_connect(self, at) -> None
      def add_text(self, text: str, at, size=2.0) -> None           # block headings
      def pin(self, ref: str, number: str) -> tuple[float, float]  # sheet position of a placed part's pin end
      def write(self, path: Path) -> None                          # (kicad_sch (version 20250114) (generator "eeschema") (generator_version "9.0") ...), lib_symbols with every used symbol once, sheet_instances (path "/" (page "1"))
  def erc(path: Path) -> list[dict]      # runs kicad-cli sch erc --format json --severity-error; returns violations
  def exported_nets(path: Path) -> dict[str, set[tuple[str, str]]]   # kicad-cli sch export netlist --format kicadsexpr, parsed: net name -> {(ref, pin)}; power-symbol refs (#...) dropped

If the netlist test below disagrees, fix the order in `pin_xy`, not the test.
- Net name of a power symbol is its Value; `3V3` uses `power:+3V3` with Value `3V3`.
